INFORME DE CIERRE DEL PASO 9 - Continuacion interactiva de confirmaciones
=========================================================================
Fecha: 2026-08-16
Proyecto: ORION-AI v2.0

OBJETIVO
--------
Completar la continuacion interactiva de confirmaciones que quedo
preparada en el PASO 8: main.py presenta la solicitud de confirmacion,
lee la respuesta del usuario y continua (o cancela) la ejecucion
pendiente a traves de la MISMA ruta de ejecucion (ToolRegistry ->
EjecutorPlan -> politica -> parametros -> EjecutorAccionesPC).

ARCHIVOS MODIFICADOS
--------------------
1. core/ejecutor/ejecutor.py
   - EjecutorPlan.ejecutar(plan, config, autorizado=None): parametro
     nuevo que contiene los "orden" de pasos CONFIRMAR que el usuario
     ya autorizo. Ese paso se ejecuta como AUTO UNA sola vez en esa
     ejecucion, sin convertir la politica de la Tool en AUTO de forma
     permanente; el resto de pasos se vuelven a evaluar. BLOQUEAR no es
     sobreescribible por la confirmacion.

2. core/cerebro.py
   - procesar(): al inicio llama a CONTINUADOR.marcar_nuevo_comando(),
     con lo que una solicitud pendiente queda obsoleta cuando ORION
     procesa otro comando.
   - _resolver_planificacion(): cuando el plan se detiene en un paso
     CONFIRMAR, enriquece la solicitud con "texto", "pasos_restantes"
     (pasos desde el pendiente en adelante, serializados) y
     "respuestas_previas" (resultados de los pasos ya ejecutados), y la
     registra en el continuador. ResultadoCerebro.solicitud y
     .solicitud_pendiente siguen apuntando a la misma solicitud.

3. main.py
   - Nuevo _atender_solicitudes(): si hay solicitud pendiente la atiende
     en un bucle (main.py sigue siendo un CLI delgado).
   - _atender_confirmacion_politica(): muestra el texto de confirmacion,
     lee la respuesta y traduce a booleano con es_afirmacion/es_negacion;
     si la respuesta no es reconocida, vuelve a pedir sin ejecutar nada.
   - _atender_solicitud_legacy(): conserva el flujo previo
     (completar_solicitud) para confirmar_accion_pc, confirmar_memoria,
     confirmar_tarea, confirmar_nota, confirmar_estado_memoria.

ARCHIVOS CREADOS
----------------
1. core/continuacion.py (capa de continuacion)
   - ContinuadorConfirmaciones: estado y logica de la solicitud pendiente.
   - continuar_solicitud(solicitud, confirmar, config=None): contrato
     publico de continuacion.
   - es_afirmacion / es_negacion: listas completas del PASO 9
     (si, si, s, confirmar, adelante, ok, vale, claro / no, n, cancelar,
     cancela, detener, deten), normalizando acentos.
   - pasos_desde / serializar_pasos / reconstruccion de Pasos.
2. tests/test_paso9_confirmaciones.py (25 tests + 18 subtests).
3. docs/diagnosticos/informe_paso9.txt (este informe).

ARQUITECTURA RESULTANTE
-----------------------
usuario -> main.py (_atender_solicitudes)
        -> cerebro.procesar() [marca comando nuevo]
        -> analizar() -> planificar() -> EjecutorPlan (politica)
        -> pausa en CONFIRMAR -> ResultadoEjecucion.paso_pendiente
        -> ResultadoCerebro.solicitud (+ pasos_restantes, respuestas_previas)
        -> core.continuacion (registra la solicitud, es la solicitud activa)
        -> continuar_solicitud(solicitud, confirmar, config)
        -> EjecutorPlan.ejecutar(subplan, config, autorizado={orden})
        -> ToolRegistry -> Tool.politica -> validacion de parametros
        -> EjecutorAccionesPC (dentro de cada Tool de PC)

No se anadio una segunda ruta de ejecucion: la continuacion reutiliza
EjecutorPlan y ToolRegistry. main.py no ejecuta Tools directamente.

CONTRATO DE CONTINUACION
------------------------
continuar_solicitud(solicitud, confirmar, config) -> ResultadoCerebro
- confirmar=True: ejecuta SOLO desde el paso pendiente (autorizado={orden})
  y continua con los pasos siguientes; no reejecuta los anteriores.
- confirmar=False: cancela sin ejecutar (accion "confirmacion_cancelada").
- Si la ejecucion vuelve a detenerse en otro CONFIRMAR, se encadena una
  nueva solicitud (volver a evaluar la politica).
- Rechazos seguros (no ejecutan nada): "solicitud_invalida" (tipo no
  confirmar_politica), "solicitud_consumida" (ya respondida),
  "solicitud_obsoleta" (otro comando ya se proceso),
  "solicitud_incompleta" (sin pasos restantes).

COMPORTAMIENTO DE CONFIRMACION
------------------------------
- AUTO: no pide confirmacion (ejecuta directo).
- CONFIRMAR: pausa con solicitud estructurada (tool, paso, parametros,
  motivo, texto_confirmacion) y pasos_restantes.
- El usuario confirma -> se ejecuta el paso pendiente una vez.
- El usuario rechaza -> no se ejecuta nada y se cancela.
- Respuesta no reconocida -> se vuelve a pedir sin ejecutar.
- La confirmacion NO convierte la Tool en AUTO: cada nueva ejecucion
  vuelve a evaluar la politica (autorizado solo vale para ese orden en
  esa ejecucion).

COMPORTAMIENTO MULTIPASO
------------------------
Paso1 AUTO, Paso2 CONFIRMAR, Paso3 AUTO:
- Paso1 -> ejecutado; Paso2 -> requiere_confirmacion; Paso3 -> no ejecutado.
- Usuario confirma: Paso2 -> ejecutado, Paso3 -> ejecutado. Paso1 NO se
  reejecuta. Respuesta compuesta final conserva el resultado del Paso1.
- Si Paso2 falla tras confirmar: Paso3 queda bloqueado (igual que
  EjecutorPlan).
- Si el usuario rechaza Paso2: Paso2 no se ejecuta y Paso3 tampoco.

PROTECCION CONTRA DOBLE EJECUCION
---------------------------------
- La solicitud activa vive en el ContinuadorConfirmaciones.
- Al continuar/cancelar se marca "_consumida" y se desactiva.
- Reintentar la misma solicitud -> "solicitud_consumida" (no ejecuta).
- procesar() marca comando nuevo al inicio: una solicitud antigua tras
  otro comando -> "solicitud_obsoleta" (no ejecuta).
